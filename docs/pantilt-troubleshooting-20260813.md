# 팬틸트 서보 추적 이상 동작 원인 분석 및 조치 보고서

- **작성일시** : 2026년 8월 13일 (목) 03:15
- **대상** : `rpi/tracking/pantilt.py`, `rpi/tracking/servo_pwm.py`
- **환경** : Raspberry Pi 5 Model B Rev 1.0 / SG90 서보 2축 / Camera Module 3 Wide

---

## 1. 증상

팬틸트가 사용자를 따라가지 못했다. 구체적으로는 아래와 같았다.

- 명령한 각도만큼 움직이지 않고 조금씩만 움직임
- 가만히 있어야 할 상황에서 좌우로 왔다갔다 함
- 틸트축이 한쪽 끝으로 휙 넘어간 뒤 돌아오지 못함

제어 게인(`KP_PAN`, `KP_TILT`, `MAX_SLEW_DPS`)을 낮추는 방향으로 여러 차례 조정했으나 증상이 개선되지 않았다. 게인 조정이 듣지 않는다는 점이 단순 튜닝 문제가 아니라는 첫 단서였다.

## 2. 원인

조사 결과 서로 독립적인 원인 **5가지**가 겹쳐 있었다. 하나를 고쳐도 나머지가 증상을 유지시켰기 때문에, 이전까지 원인 파악이 어려웠다.

### 2-1. 소프트웨어 PWM 사용 (근본 원인)

Pi 5에서는 기존 `RPi.GPIO`가 동작하지 않아 `rpi-lgpio 0.6` 호환 레이어가 대신 설치되어 있었다. `import RPi.GPIO`가 실제로는 이 호환 레이어를 가리킨다.

```
RPi/GPIO/__init__.py  →  Copyright (c) 2022-2023 Dave Jones
rpi-lgpio 0.6
```

이 구현은 순수 파이썬이며 PWM 펄스를 백그라운드 스레드에서 생성한다. 서보 제어에서는 이것이 치명적이다.

- 펄스 폭 0.5\~2.5ms가 0\~180°에 대응 → **1µs ≈ 0.09°**
- 100µs 지연 = 약 9°, 1ms 지연 = 약 90°

`main.py`는 FaceMesh, Pose, EfficientDet를 한 루프에서 실행해 CPU를 포화시킨다. 이 상태에서 PWM 스레드가 밀리면 펄스 폭이 통째로 틀어진다. **명령한 각도와 실제 출력 펄스가 달랐으므로, 게인을 아무리 조정해도 효과가 없었다.**

한편 `/boot/firmware/config.txt:55`에는 하드웨어 PWM 오버레이가 이미 설정되어 있었다.

```
dtoverlay=pwm-2chan,pin=12,func=4,pin2=13,func2=4
```

즉 GPIO 12/13을 하드웨어 PWM으로 쓰도록 설정해두고도, 코드는 같은 핀을 소프트웨어 PWM으로 점유하고 있었다. 두 방식이 핀 mux를 서로 뺏는 상태였다.

### 2-2. 팬/틸트 핀 반대 배정

코드는 `PAN_GPIO = 12`, `TILT_GPIO = 13`으로 배정되어 있었으나, 실측 결과 정반대였다.

| GPIO | PWM 채널 | 실제 축 |
|------|----------|---------|
| 12 | 0 | 틸트 (상하) |
| 13 | 1 | 팬 (좌우) |

**팬 보정값이 틸트 서보로, 틸트 보정값이 팬 서보로 출력되고 있었다.** PWM 백엔드를 고쳐도 이 문제는 그대로 남았을 것이다.

### 2-3. 서보 혼 장착 오프셋

캘리브레이션 도구로 측정한 결과, 두 축 모두 중립이 가동 범위의 양 끝에 걸려 있었다.

| 축 | 중립 각도 | 펄스 폭 | 잔여 가동범위 |
|----|-----------|---------|---------------|
| 틸트 | 약 175° | 약 2.44ms | 한쪽으로 5° |
| 팬 | 15° 미만 | 0.67ms 미만 | 한쪽으로 15° |

추적은 중립을 기준으로 양방향 이동이 필요한데, 한쪽 여유가 사실상 0이었다. 펄스 범위 0.5\~2.5ms는 이미 서보 규격의 한계이므로 소프트웨어로 보정할 수 없었다.

### 2-4. 서보 혼 고정 불량

혼을 재장착한 뒤에도 수평 각도가 계속 변했다.

| 시점 | 수평 각도 |
|------|-----------|
| 최초 측정 | 약 175° |
| 혼 재장착 직후 | 90° |
| 이후 재측정 | 약 20° |

캘리브레이션 값이 스스로 변한다는 것은 혼이 스플라인 위에서 미끄러지고 있다는 뜻이다. 2-5의 부호 오류로 틸트가 하한까지 폭주해 기구의 물리적 스톱을 계속 밀어붙였고(스톨), 그때 스플라인 이가 넘어간 것으로 판단된다. SG90 혼의 중앙 고정 나사가 체결되지 않으면 압입만으로는 부하를 견디지 못한다.

> 초기에 이를 서보 토크 부족으로 판단했으나 오진이었다. SG90은 1.8kg·cm이고 카메라와 브래킷 요람을 합쳐도 약 30g, 회전축에서 3cm 기준 0.09kg·cm로 정격의 5% 수준이다. `vcgencmd get_throttled` 결과도 `0x0`으로 저전압 이력이 없었다.

### 2-5. 틸트 제어 부호 반대

혼 재장착으로 링키지가 뒤집히면서 각도-방향 관계가 바뀌었는데 부호가 따라가지 않았다. 추적 로그가 이를 명확히 보여준다.

```
[PanTilt] FACE  pan=88.5  tilt=50.0  err_x=  6  err_y=-181
[PanTilt] FACE  pan=88.5  tilt=50.0  err_x= -4  err_y=-195
[PanTilt] FACE  pan=88.5  tilt=50.0  err_x= -7  err_y=-218
[PanTilt] FACE  pan=88.5  tilt=50.0  err_x=-11  err_y=-239
```

`tilt`가 하한 50°에 고정된 상태에서 `err_y`가 -181 → -239로 **계속 증가**했다. 오차를 키우는 보정은 방향이 반대라는 뜻이다. 같은 로그에서 `err_x`는 -11, 4, -1로 0 부근을 오갔으며, 이것이 부호가 맞을 때의 정상 형태다.

### 2-6. POSE 분기에서 틸트 정지 (부수 문제)

얼굴을 놓치고 어깨만 검출되는 상황에서 틸트축을 의도적으로 고정하도록 되어 있었다. 원래는 상향 폭주를 막기 위한 대응책이었으나, 2-5의 부호 오류가 진짜 원인이었다.

이 고정 때문에 **복구 가능한 상태가 영구 상태로 바뀌었다.** 틸트가 아래로 치우침 → 얼굴이 화면 밖으로 이탈 → 어깨만 검출 → POSE 분기 진입 → 틸트 고정 → 복귀 불가.

## 3. 조치

### 3-1. 하드웨어 PWM 백엔드 신규 작성

`rpi/tracking/servo_pwm.py`를 추가하고 `/sys/class/pwm` 인터페이스로 RP1 하드웨어 PWM을 직접 제어하도록 했다. 타이머가 실리콘에 있으므로 CPU 부하와 무관하게 펄스 폭이 정확하다.

- 50Hz 프레임, 펄스 0.5\~2.5ms (기존 duty 2.5\~12.5%와 동일한 대응 관계 유지)
- `enable` → `period` → `duty_cycle` 순서로 초기화 (신규 export 시 period가 0이라 duty를 먼저 쓰면 거부됨)
- udev의 권한 설정 지연에 대비한 재시도 로직 포함
- `sudo` 불필요 (gpio 그룹 권한으로 접근 가능)

`RPi.GPIO`와는 상호 배타적이다. 나중에 실행된 쪽이 핀 mux를 가져가므로, 이 모듈을 쓰는 코드에서는 `RPi.GPIO`를 import하면 안 된다.

> 오버레이가 설정한 PWM 기능으로 핀을 되돌리기 위해 **재부팅 1회**가 필요했다. `rpi-lgpio`가 핀 mux를 일반 GPIO로 변경해둔 상태였기 때문이다.

### 3-2. 캘리브레이션 도구 신규 작성

`rpi/tools/servo_check.py`를 추가했다. 추적 로직 없이 서보만 직접 구동하므로, 제어 문제와 기구 문제를 분리해 진단할 수 있다. 실제로 2-4의 오진을 바로잡은 것이 이 도구였다.

축 이름 대신 GPIO 번호로 지칭한다(`a` = GPIO12, `b` = GPIO13). 어느 쪽이 팬이고 틸트인지를 확인하는 것이 이 도구의 목적이므로, 축 이름을 미리 붙이면 전제를 가정하게 되기 때문이다.

```
a 120     GPIO12를 120도로      b 120    GPIO13을 120도로
a +5      5도 증가              a -5     5도 감소
sweep a   전 범위 순회
off       양쪽 구동 중지        hold     구동 재개
s         현재 각도/펄스폭 표시  q        종료
```

### 3-3. 기구 조정

- 팬/틸트 양축의 혼을 재장착하여 **90°가 정면·수평**이 되도록 맞춤
- 혼 중앙 고정 나사 체결
- `sweep` 후 90° 복귀 시 수평이 유지되는지로 고정 상태 검증

### 3-4. `pantilt.py` 수정

| 항목 | 수정 전 | 수정 후 |
|------|---------|---------|
| PWM 백엔드 | `RPi.GPIO` (소프트웨어) | `ServoPWM` (하드웨어) |
| 팬 서보 | GPIO12 | GPIO13 (채널 1) |
| 틸트 서보 | GPIO13 | GPIO12 (채널 0) |
| `TILT_CENTER` | 80 | 90 |
| `TILT_MIN/MAX` | 50\~120 | 50\~130 (90 기준 대칭) |
| `TILT_SIGN` | 없음 | `+1` (실측) |
| `PAN_SIGN` | 없음 | `+1` (실측) |
| `KP_PAN` / `KP_TILT` | 0.01 | 0.04 |
| `MAX_SLEW_DPS` | 1.5 | 20 |
| `RECENTER_DPS` | 1.0 | 8.0 |
| full-face 시 동작 | PWM을 0으로 차단 | 각도 유지 |
| POSE 시 틸트 | 고정 | 코 추적 / 상향 탐색 |

**축 방향 상수 도입.** `TILT_SIGN`, `PAN_SIGN`을 분리해 장착 방향에 의존하는 부분을 한 곳으로 모았다. 기구를 다시 손보더라도 이 상수 하나만 바꾸면 되며, POSE 탐색 방향도 `-TILT_SIGN`으로 파생시켜 자동으로 따라오게 했다.

**게인 상향.** 기존 값은 고장난 백엔드를 상대로 튜닝된 값이었다. 서보가 명령을 따르지 않으니 계속 낮춘 결과였고, 정상 동작하는 지금은 얼굴을 따라잡지 못하는 수준이었다.

**full-face 시 PWM 차단 제거.** 소프트웨어 PWM의 지터를 줄이기 위한 대응책이었으나 하드웨어 PWM에는 해당 지터가 없다. 오히려 펄스를 끊으면 유지 토크가 사라져 카메라 무게로 틸트가 처졌다가 추적 재개 시 튀어 오르는 문제가 있었다.

**POSE 분기 개선.** Pose 모델은 자체 코 랜드마크를 보유한다. FaceMesh 실패의 흔한 원인은 눈이 가려지는 것인데, 코는 그 영향을 받지 않는다. 따라서 얼굴 미검출이 곧 머리 위치 불명을 의미하지 않는다.

- `nose.visibility ≥ 0.5` → 코를 기준으로 계속 추적 (`POSE/nose`)
- 미만 → 상향 탐색 (`POSE/seek`). 어깨는 보이는데 머리가 없다면 머리는 화면 위쪽에 있다는 뜻이다. `TILT_MIN`에서 멈추므로 기존 폭주와 달리 무한정 진행하지 않는다

## 5. 재작업 시 참고사항

**축 방향은 반드시 실측할 것.** 이번 작업에서 방향 판정을 두 차례 번복했다. 이전 로그를 근거로 삼았는데 그 사이에 혼을 재장착해 링키지가 뒤집혔기 때문이다. **마지막 기구 변경 이전에 기록된 로그는 다른 기계를 설명하는 자료다.** 혼을 만졌다면 `servo_check.py`로 다시 측정해야 하며, 명령 한 번이면 확인된다. 이 내용은 `pantilt.py` 주석에도 명시해두었다.

**진단 시 `servo_check.py`를 먼저 쓸 것.** `main.py`는 추적 보정이 계속 개입해 제어 문제와 기구 문제를 구분하기 어렵다. 실제로 토크 부족 오진을 바로잡은 것이 이 분리였다.

**두 프로그램을 동시에 실행하지 말 것.** 같은 PWM 채널을 점유하므로 서로 충돌한다.

**증상만으로 단정하지 말 것.** 이번 건은 원인이 5가지 겹쳐 있어 하나를 고쳐도 증상이 유지됐다. 디버그 로그(`DEBUG_TRACKING`)에서 분기명과 각도, 오차를 함께 보면 기구 문제(각도는 정상인데 물리적으로 어긋남)와 제어 문제(각도 자체가 한계로 이동)를 구분할 수 있다.

**혼 고정 나사를 반드시 체결할 것.** 압입만으로는 부하 시 스플라인이 미끄러진다. 재장착 후에는 `sweep` → 중립 복귀로 각도가 유지되는지 검증해야 한다.
